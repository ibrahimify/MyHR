## Interpretation Rules

- Archived documents are evidence of project evolution, not live authority.
- Do not silently rewrite archived material to match later conclusions.
- When citing a result or decision, start from the [documentation guide](../README.md) and follow its current or dated evidence source.
- A later correction may supersede an archived status summary without erasing the original finding or chronology.
- Moving a file into this archive does not make it disposable; deletion requires a separate preservation review.

## Metadata Expectations

Each future archive move should be recorded in this index or an accompanying manifest with:

- archived path and original path;
- document title and role;
- creation or best-known source date;
- source revision or provenance when available;
- file format and SHA-256 checksum, especially for binary or legacy files;
- reason for archival;
- current or superseding document, if one exists;
- relationship between editable and rendered forms, such as DOCX and PDF;
- confidentiality, publication, or retention constraints where applicable.

Unknown historical metadata should be marked `unknown`; it must not be inferred. Checksums describe preserved bytes and should be recalculated only when a deliberately versioned archive copy is added.
